1. PROJENİN GENEL AMACI
================================================================

Bu proje, kullanıcıların kendilerini motive etmelerine yardımcı
olan bir web uygulamasıdır. Kullanıcı hesabı oluşturup giriş
yapabilir. Giriş yaptıktan sonra şunları yapabilir:

  - Motivasyon alıntıları okuyabilir ve favorilere ekleyebilir
  - Kişisel hedefler belirleyebilir ve ilerleme takibi yapabilir
  - Günlük ruh hali notu yazabilir (kişisel günlük)
  - Anlık motivasyon bildirimi alabilir
  - Başarı rozetleri kazanabilir (örn: 7 gün üst üste giriş)
  - Profil sayfasında tüm istatistiklerini görebilir

Kullanılan teknolojiler:
  - Python + Flask  → web sunucusu ve sayfa yönlendirme
  - SQLite          → veritabanı (hafif, kurulum gerektirmez)
  - HTML + CSS      → sayfa tasarımı
  - JavaScript      → sayfa içi dinamik işlemler (AJAX)
  - Bootstrap 5     → hazır CSS bileşenleri

3. NESNE YÖNELİMLİ PROGRAMLAMA (OOP) KULLANIMI
================================================================

Projede OOP'un üç temel kavramı kullanıldı:

---------------------------------------------------------------
3.1 KALITIM (Inheritance)
---------------------------------------------------------------

base_model.py dosyasında "BaseModel" adında bir temel sınıf
oluşturdum. Bu sınıf; id ve created_at (oluşturulma tarihi)
alanlarını ve to_dict() metodunu içeriyor.

Diğer tüm sınıflar bu BaseModel'den türüyor:

  BaseModel
  ├── User       (kullanıcı)
  ├── Goal       (hedef)
  ├── Note       (not)
  ├── Quote      (alıntı)
  └── Notification
        ├── MotivasyonBildirimi
        ├── HedefBildirimi
        └── RozetBildirimi

Kalıtımın faydası: Her sınıfa ayrı ayrı id ve created_at
yazmak zorunda kalmıyorum. Bir kez BaseModel'e yazıyorum,
hepsi otomatik miras alıyor.

Örnek (src/data/user.py):

  class User(BaseModel):          ← BaseModel'den türüyor
      def __init__(self, ...):
          super().__init__(...)   ← Ebeveyn sınıfı çağırıyor
          self.username = username
          ...

---------------------------------------------------------------
3.2 POLİMORFİZM (Polymorphism)
---------------------------------------------------------------

src/services/notification.py dosyasında polimorfizm kullandım.

Temel Notification sınıfında "format_message()" adında bir
metot tanımladım ama içini boş bıraktım (NotImplementedError).
Alt sınıfların her biri bu metodu kendi şekilde dolduruyor:

  class Notification(BaseModel):
      def format_message(self):
          raise NotImplementedError(...)  ← Alt sınıf yazacak

  class MotivasyonBildirimi(Notification):
      def format_message(self):
          return f"[Motivasyon - {self.kategori}] {self.message}"

  class HedefBildirimi(Notification):
      def format_message(self):
          return f"[Hedef Tamamlandı] {self.hedef_adi}: ..."

  class RozetBildirimi(Notification):
      def format_message(self):
          return f"[Yeni Rozet: {self.rozet_adi}] ..."

Polimorfizmin faydası: Üç farklı bildirim türü aynı metot adını
(format_message) kullanıyor ama her biri farklı sonuç üretiyor.
Hangi tür bildirim olduğuna bakmadan .format_message() diyebiliyorum.

---------------------------------------------------------------
3.3 KAPSÜLLEME (Encapsulation)
---------------------------------------------------------------

Her sınıf kendi verilerini ve mantığını içinde tutuyor.
Dışarıdan direkt veri değiştirmek yerine metodlar kullanılıyor.

Örnek - Goal sınıfında (src/data/goal.py):

  def update_progress(self, value):
      self.progress = max(0, min(100, int(value)))
      if self.progress == 100:
          self.is_completed = True

  İlerlemeyi direkt self.progress = 150 yazmak yerine
  update_progress(150) metodunu çağırıyorum. Bu sayede
  değer her zaman 0-100 arasında kalıyor.

Örnek - User sınıfında (src/data/user.py):

  def update_streak(self):
      ... (giriş günü hesaplaması)
      return self.streak

  Seriyi manuel hesaplamak yerine bu metodu çağırıyorum.

4. VERİTABANI TASARIMI
================================================================

SQLite kullandım. src/data/database.py dosyasında 7 tablo var:

  users       → Kullanıcı bilgileri (id, kullanıcı adı, şifre, seri)
  quotes      → Motivasyon alıntıları (metin, yazar, kategori)
  favorites   → Hangi kullanıcı hangi alıntıyı favoriledI
  goals       → Hedefler (başlık, açıklama, ilerleme, bitiş tarihi)
  notes       → Günlük notlar (başlık, içerik, ruh hali)
  notifications → Bildirimler (başlık, mesaj, okundu mu)
  badges      → Rozetler (isim, koşul türü, koşul değeri)
  user_badges → Hangi kullanıcı hangi rozeti kazandı

Tablolar arasındaki ilişkiler:
  - Her goal, note, notification bir kullanıcıya ait (user_id)
  - favorites tablosu user_id ve quote_id'yi birbirine bağlıyor
  - user_badges tablosu user_id ve badge_id'yi birbirine bağlıyor

Veritabanı ilk çalıştırmada otomatik oluşuyor:
  init_db()  → Tabloları oluşturur
  seed_data() → Örnek alıntıları ve rozetleri ekler

5. FLASK KULLANIMI VE SAYFA YÖNLENDİRME
================================================================

Flask bir Python web framework'ü. Kullanıcı tarayıcıda bir URL'e
gittiğinde Flask hangi Python fonksiyonunun çalışacağına karar veriyor.

Blueprint sistemi kullandım. Her konu için ayrı bir dosya var
(auth.py, goals.py, notes.py...). Bunları Blueprint ile grupladım
ve app.py'de birleştirdim.

Örnek - goals.py:

  goals_bp = Blueprint('goals', __name__)

  @goals_bp.route('/goals')           ← URL adresi
  @login_required                     ← Giriş yapılmış mı?
  def goals():
      ... veritabanından hedefleri çek
      return render_template('goals.html', goals=goals_list)

app.py'de hepsini birleştirdim:

  from src.modules.auth import auth_bp
  from src.modules.goals import goals_bp
  ...
  app.register_blueprint(auth_bp)
  app.register_blueprint(goals_bp)

Flask'a şablonların (HTML) nerede olduğunu söyledim:
  app = Flask(__name__, template_folder='src/ui', static_folder='assets')

6. ŞİFRE GÜVENLİĞİ
================================================================

Şifreleri veritabanında düz metin olarak saklamak tehlikelidir.
Bu yüzden src/utils/helpers.py dosyasında hash kullandım.

Kayıt olurken:
  1. Rastgele bir "salt" (tuz) üretiyorum (16 karakter)
  2. Şifreyi + salt'ı birleştirip SHA-256 ile şifreliyorum
  3. "salt:hash" formatında veritabanına kaydediyorum

  def hash_password(password):
      salt = secrets.token_hex(16)
      hash_val = hashlib.sha256((password + salt).encode()).hexdigest()
      return f"{salt}:{hash_val}"

Giriş yaparken:
  1. Veritabanındaki salt'ı alıyorum
  2. Girilen şifreyi + salt ile aynı işlemi yapıyorum
  3. Sonuç eşleşiyorsa şifre doğrudur

  def verify_password(password, stored_hash):
      salt, hash_val = stored_hash.split(':')
      computed = hashlib.sha256((password + salt).encode()).hexdigest()
      return computed == hash_val

7. GİRİŞ KONTROLÜ (login_required)
================================================================

src/utils/auth.py dosyasında bir dekoratör yazdım.
Dekoratör, bir fonksiyonu sarmalayan özel bir fonksiyondur.

  def login_required(f):
      @wraps(f)
      def decorated(*args, **kwargs):
          if 'user_id' not in session:
              return redirect(url_for('auth.login'))
          return f(*args, **kwargs)
      return decorated

Kullanımı çok basit - korunan sayfanın üstüne yazıyorum:

  @goals_bp.route('/goals')
  @login_required          ← Giriş yoksa login sayfasına at
  def goals():
      ...

Bu dekoratör olmadan her sayfaya ayrı ayrı giriş kontrolü
kodum olması gerekirdi. Dekoratör bu tekrarı önlüyor.

10. ROZET SİSTEMİ NASIL ÇALIŞIYOR?
================================================================

Rozet kazanma işlemi src/modules/notifications.py içinde
check_badges() fonksiyonunda gerçekleşiyor.

Adımlar:
  1. Kullanıcının güncel istatistiklerini çek
     (kaç hedef tamamladı, kaç not yazdı, serisi kaç gün...)

  2. Veritabanındaki tüm rozetleri çek

  3. Her rozet için Badge sınıfının check_condition() metodunu çağır

     def check_condition(self, user_stats):
         deger = user_stats.get(self.condition_type, 0)
         return deger >= self.condition_value

  4. Koşul sağlanıyorsa ve rozet daha önce kazanılmamışsa:
     - user_badges tablosuna kaydet
     - RozetBildirimi oluştur (polimorfizm)
     - Bildirim tablosuna ekle
     - Ekranda popup göster

Bu kontrol dashboard'a her girildiğinde çalışıyor.

11. GÜNLÜKSERİ (STREAK) SİSTEMİ
================================================================

Kullanıcının kaç gün üst üste giriş yaptığını takip ediyorum.
Bu hesaplama User sınıfının update_streak() metodunda yapılıyor.

Mantık:
  - Son giriş tarihi ile bugünü karşılaştır
  - Fark 1 gün ise: seri + 1
  - Fark 0 gün ise: aynı gün, seri değişmez
  - Fark 2+ gün ise: seri sıfırla (1'e döner)

  def update_streak(self):
      fark = (today - last).days
      if fark == 1:
          self.streak += 1
      elif fark > 1:
          self.streak = 1
